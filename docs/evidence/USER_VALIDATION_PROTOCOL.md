# Критические рыночные доказательства — ПРОТОКОЛ, НЕ РЕЗУЛЬТАТЫ

Эта страница отделяет реализованную вычислительную проверку от **пока не собранных** данных реальных пользователей ОМА. Никого не опрашивали автоматически, никакие ответы не придуманы.

## 1. Полевое исследование до защиты

- 12–20 добровольных интервью с людьми, которые покупали товары для ремонта или дома в последние 3 месяца (сегмент и источник рекрутинга фиксировать).
- 5 коротких задач на прототипе: «Починить смеситель», «Купить комплект для полки», «Найти готовый проект», «Проверить последовательность», «Сформировать заказ».
- Сравнивать с текущим путем: отдельно найти товары, проверить совместимость, составить список, заказать услуги.
- Записывать время до готовой корзины и **завершение без помощи**. Нельзя предлагать пользователю нужный ответ.
- Каждый респондент добровольно соглашается на сбор обезличенных результатов; контакты и адреса сюда не вносятся.

## 3. Предварительные KPI пилота (ГИПОТЕЗЫ)

| KPI | Что измеряем | Как сравниваем |
|---|---|---|
| Task success | Доля завершивших задачу без подсказок | Контрольный поток каталога vs OMA ONE |
| Time to basket | Время от открытия до корректной корзины | Медиана, p90; учитывать незавершённые |
| Error avoidance | Ошибочные или несовместимые товары в списке | Независимый эксперт по утверждённым правилам |
| Revisit | Возврат через 30 дней для новой задачи | Когорта и сопоставимый контроль |
| Incremental contribution | Вклад заказа после *всех* переменных расходов | Данные ОМА, не модельный калькулятор |
| Partner fill rate | Доля услуг, исполненных в обещанный слот | Только после заключения договоров |
| Pulse false alerts | Доля неподтверждённых оповещений | Ручной review до отправки |

Порог успешности и выборку утверждать **до** пилота, а не после просмотра результатов.

## 4. Что просить у ОМА

- Read-only товарный фид с SKU, единицами, региональной ценой, наличием и временем обновления.
- Тестовый метод импорта набора товаров в корзину, без реальной оплаты.
- Обезличенные агрегаты по возвратам/причинам отказов, без адресов клиентов.
- Оценку валовой маржи, доставки, сервиса и возвратов от уполномоченного владельца данных.
- Один эксперт по товарам и один ответственный за услуги для утверждения правил AntiFail и Domino.

## 5. Ограничения и допуск к внедрению

- Нельзя публиковать чужие проекты в DNA без разрешения и модерации.
- Нельзя продавать услуги неутвержденных мастеров как услуги ОМА.
- Нельзя автоматически ставить предупреждения PULSE без экспертной проверки.
- Нельзя заявлять о реальном ускорении, экономии, конверсии или ROI без контрольной группы.
- Нельзя использовать логотип и внешний вид ОМА для публичного релиза без разрешения владельца бренда.

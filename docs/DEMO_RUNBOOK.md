# OMA ONE — финальный регламент демонстрации

**Версия:** `feature/oma-golden-flow`. **Статус:** неофициальный хакатонный прототип, данные синтетические.

## Перед защитой (на Mac)

1. Зафиксировать SHA демонстрируемой сборки: `git rev-parse HEAD`. **Не переключаться на `main`**, там старая версия.
2. Выполнить `npm ci`, `npm run typecheck`, `npm run test:proof`, `npm test` (PostgreSQL и `initdb`/`pg_ctl` обязательны), `npm run test:e2e`, `npm run check:ios-evidence`.
3. Выполнить `xcodebuild -project ios/OMAOne.xcodeproj -scheme OMAOne -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build`.
4. Открыть Xcode и **лично пройти сценарий на том устройстве, которое будет на сцене**. Сборка для симулятора не означает, что приложение протестировано на iPhone.
5. Записать короткое видео с экрана устройства: главное меню → блокировка неверного крепежа → исправленный вариант → список покупок → корзина → проект → Proof. Сохранить видео локально на телефоне и ноутбуке.
6. Проверить заряд устройства, режим «Не беспокоить», подключение проектора и работу демонстрации без Wi-Fi.

## Трёхминутный сценарий

**0:00–0:25 — проблема.** Покупатель хочет повесить полку, но может купить неподходящий крепёж и лишние материалы.

**0:25–1:05 — AntiFail.** На главной выбрать «Хочу повесить полку», указать стену из гипсокартона и бетонный дюбель. Показать явную блокировку. Затем выбрать подходящий по демонстрационным правилам анкер; отметить проверки стены, проводки и инструкции. Обязательно проговорить: это предварительная рекомендация, а не подтверждение безопасности монтажа.

**1:05–1:40 — ZeroBuy и корзина.** Отметить защитные очки как имеющиеся дома. Продемонстрировать уменьшение списка покупок, добавление позиций в корзину и демо-оформление. Подчеркнуть, что каталог, остатки и цены тестовые.

**1:40–2:15 — Domino и Proof.** Отметить этапы по порядку, сохранить черновик и продемонстрировать возвращение в «Мой дом». Объяснить разницу между `SELF_REPORTED` без фото, `EVIDENCE_SUBMITTED` с фото и отдельной будущей экспертной проверкой.

**2:15–3:00 — эффект для ОМА.** Одна непрерывная задача связывает подбор материалов, предотвращение ошибок и путь к корзине. Описать SyncCity, DNA, FORGE и PULSE как отдельные демонстрационные расширения, не пытаться проходить их все на сцене.

## План Б

- Если iOS не запускается: показать заранее записанное **реальное видео работающего приложения**, а не макет.
- Если сломана сеть: показать нативную офлайн-полку; для Evidence Lab запустить `npm run evidence`, открыть `http://localhost:8790/proof.html`.
- Если не работает PostgreSQL: не демонстрировать серверный путь заказов; использовать только проверенную офлайн-демонстрацию.
- Если приложение не прошло ручную проверку на целевом iPhone: использовать симулятор или записанный проверенный сценарий; не заявлять о проверке на физическом устройстве.

## GO / NO-GO

**GO:** выбранный билд собирается; блокировка несовместимого крепежа работает; смета и корзина обновляются; проект сохраняется; Proof не выдаёт неподтверждённую экспертную оценку; имеется резервное видео.

**NO-GO для живой демонстрации:** приложение падает, не открывает основной сценарий, пропускает обязательную блокировку, теряет сохранённые данные или показывает реальные финансовые/инженерные гарантии, которых нет. Тогда использовать резервное видео и объяснить ограничения.

## Нельзя утверждать

Нет официальной интеграции ОМА, проверенных реальных цен, оплат, заказов, инженерной сертификации и независимого экспертного Proof. У проекта есть работающие демонстрационные правила и интеграционные тесты, но фактические результаты **каждого последнего запуска** нужно предъявлять отдельно.

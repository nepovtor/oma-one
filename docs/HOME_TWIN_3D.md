# OMA HOME TWIN — нативная 3D-квартира (экспериментальная ветка)

**Ветка:** `feature/oma-home-twin-3d`. Новый модуль расположен в разделе OMA ONE → «OMA HOME TWIN · 3D», а также доступен с главной по кнопке «Моя квартира · 3D» и из «Мои проекты». Существующие вкладки магазина и восемь алгоритмов сохранены.

## Что работает

- **Реальная SceneKit-сцена**, не скриншот и не плоская иллюстрация: можно вращать квартиру и масштабировать двумя пальцами.
- Схематичная квартира из 1–4 комнат; пользователь вручную выбирает название, тип комнаты и приблизительные размеры (2,5–5,8 м). Сетка размещается автоматически.
- Стены, пол, освещение и соответствующая назначению мебель физически появляются/меняются в 3D при отметке этапа выполнения.
- Режим «Показать цель» визуализирует желаемый результат **без изменения статусов и процентов**.
- Прогресс рассчитывается из пользовательских отметок. Комнаты и этапы сохраняются в локальном `UserDefaults` после перезапуска.
- Фото конкретной комнаты можно выбрать из медиатеки. Оно сжимается и хранится локально в Documents/OMAHomeTwinPhotos; снимок служит **ориентиром**, а не автоматической реконструкцией геометрии.
- Связь с существующей полкой: если в OMA ONE создан проект установки полки, он учитывается в прогрессе выбранной комнаты. В 3D полка появляется только после записи `SELF_REPORTED` или `EVIDENCE_SUBMITTED` в существующем локальном Proof. Ни один из этих статусов **не означает экспертную проверку**.

## Как проверить на Mac

```bash
git fetch origin
git switch feature/oma-home-twin-3d
git pull --ff-only origin feature/oma-home-twin-3d
npm ci
npm run typecheck
npm run test:proof
npm test
npm run check:ios-evidence
xcodebuild -project ios/OMAOne.xcodeproj -scheme OMAOne -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

В Xcode нажать Run на выбранном iPhone Simulator и пройти путь:

1. Главная → «Моя квартира · 3D»: 3D-модель открывается без сети. Повернуть и приблизить.
2. «Показать цель» → квартира выглядит законченной, **процент не меняется**.
3. Выбрать комнату, поставить отметки «Стены», «Пол», «Освещение», «Мебель»: геометрия и прогресс меняются.
4. Добавить третью комнату, указать имя, тип и размеры; закрыть и заново открыть приложение — данные сохраняются.
5. Выбрать фото комнаты, убедиться, что оно показано как референс, а 3D не заявляется точным сканом.
6. В OMA ONE сохранить черновик полки, вернуться в HOME TWIN: статус «запланирована», модель не показывает её как выполненную.
7. Выполнить все обязательные шаги полки, сделать запись Proof без фото/с фото, вернуться в HOME TWIN: полка появляется в 3D, процент обновляется; экспертного статуса нет.
8. Изменить параметры сохранённой полки, повторно сохранить, проверить, что статус выполнения сброшен и объект пропадает из фактического 3D-вида.

## Ограничения

Это персональная **схематичная** модель, не фотограмметрия, не автоматическое построение квартиры из снимков и не точный обмер. Нет LiDAR-сканирования, экспорта USDZ, распознавания мебели, облачной синхронизации или связи с реальными заказами ОМА. Комнаты автоматически располагаются сеткой без редактирования положения стен и дверей. Другие сценарии OMA ONE пока отмечаются вручную, а не синхронизируются с Proof полки. Модель не предназначена для инженерных расчётов ремонта.

**Проверяемость:** статический контракт сцены и бизнес-модель имеют новые тесты `tests/home-twin.test.ts` и `tests/home-twin.swift`. Xcode-сборку и визуальный ручной прогон требуется выполнить на Mac с Xcode; результаты не следует объявлять пройденными, пока команды реально не выполнены.

# Пользовательские сценарии, SLA и критерии приёмки

Статус: **проект для согласования**. Числа ниже — стартовое предложение; они не считаются SLA ОМА до подтверждения владельцами интеграций.

## Основной сценарий: задача → корзина

1. Авторизованный клиент открывает раздел OMA ONE.
2. Выбирает один из опубликованных сценариев.
3. Отвечает только на вопросы, необходимые для расчёта и безопасности.
4. Сервис получает актуальные товарные данные, цену и доступность для выбранного региона.
5. Версионированные правила формируют комплект и объясняют блокировки/допущения.
6. Клиент при желании отмечает уже имеющиеся товары.
7. Перед добавлением система повторно проверяет цену, доступность и совместимость.
8. Комплект передаётся в существующую корзину ОМА; сервер ОМА возвращает фактический состав и сумму.
9. Клиент продолжает обычное оформление в ОМА. OMA ONE не принимает оплату и не создаёт собственный заказ.

## Критерии приёмки основного сценария

- Пользователь без действующей сессии направляется в SSO и возвращается в тот же сценарий.
- Клиент не может получить или изменить чужой расчёт заменой идентификатора в URL/теле запроса.
- У каждого результата есть `ruleVersion`, дата проверки и источник товарных данных.
- Расчёт не использует цену, количество или скидку, присланные браузером, как доверенное значение.
- Обязательные вопросы нельзя пропустить; невалидные единицы и отрицательные количества отклоняются.
- Блокирующее предупреждение не обходится кнопкой «всё равно добавить».
- При изменении цены/остатка пользователь видит различие до перехода к оформлению.
- Повтор одного и того же запроса добавления с тем же idempotency key не дублирует позиции.
- Итог, показанный после импорта, совпадает с ответом корзины ОМА, а не с локальным расчётом.
- Для неподдерживаемой задачи система честно отказывает и даёт безопасный следующий шаг.

## Негативные и восстановительные сценарии

### Нет товара

- Позиция помечается недоступной для выбранного места получения.
- Автоматическая замена возможна только из одобренного списка и с повторной проверкой всего комплекта.
- Без проверенной замены комплект не объявляется полным.

### Изменилась цена или доступность

- Ответ `409/412` приводит к обновлению комплекта, а не к молчаливому оформлению старых данных.
- Пользователь видит, какие позиции изменились и когда получены новые данные.

### Недоступно API ОМА

- Нельзя показывать кэш как актуальный остаток без явной маркировки времени.
- Добавление в корзину блокируется, если сервер не может подтвердить критические данные.
- Пользователь получает понятное сообщение и возможность повторить запрос.

### Опасная или неоднозначная задача

- Сценарий останавливается на заранее утверждённом правиле.
- Не генерируется пошаговая инструкция, способная заменить специалиста.
- Показываются причина остановки и официальный канал консультации/сервиса, если он согласован.

### Конфликт редактирования правила

- Опубликованная версия неизменяема.
- Новая версия создаётся отдельно, проходит экспертную проверку и имеет план отката.

## Сценарии расширенного пилота

### Мастер

Клиент выбирает подходящую услугу, видит полную цену, зону и слот, подтверждает запись и отслеживает статус. Мастер получает контакты только после назначения. Повтор запроса не создаёт дубль брони.

### SyncCity

Клиент видит только город, зону с низкой точностью, слот, цель группы и условия скидки. Адреса, ФИО и контакты участников не раскрываются. До вступления показаны дата, порог, правила отмены и способ пересчёта.

### Proof и OMA DNA

После завершения клиент может загрузить фото и комментарий. До сохранения удаляются метаданны; объект приватный по умолчанию. Публикация в DNA требует отдельного действия и модерации. Адаптация DNA всегда заново рассчитывает товары, цены, остатки и правила.

### OMA FORGE

Клиент может один раз выразить интерес к комплекту и отозвать его. Счётчик не является предзаказом. Состав, цена и срок публикуются менеджером отдельно; одни голоса не меняют цену.

### OMA PULSE

Сигнал получает статус «требует проверки». Внешнее уведомление создаётся только после решения эксперта и содержит источник, дату, уровень уверенности и канал оспаривания.

### Внешний AI

Перед отправкой запроса данные минимизируются, а секреты и вложения не передаются. Ответ модели не может изменить цену, остаток, корзину, роль, статус модерации или блокирующее правило. При timeout/ошибке основной сценарий продолжает работать без AI.

## Операторский сценарий

1. Оператор создаёт черновик из опубликованной версии.
2. Добавляет источник, дату проверки, товары, условия и тестовые примеры.
3. Автоматические тесты проверяют схему, циклы зависимостей и граничные количества.
4. Технический/товарный эксперт подписывает содержание.
5. Менеджер публикует версию в ограниченный rollout.
6. Система фиксирует автора, утверждающего, diff, дату и причину изменения.

Приёмка: один человек не может создать и самостоятельно опубликовать правило; откат не уничтожает историю.

## Предварительные SLO пилота

| Показатель | Цель пилота | Как измерять |
|---|---:|---|
| Доступность пользовательского API OMA ONE | 99,5% в календарный месяц | Успешные запросы без плановых окон |
| p95 открытия сценария | ≤ 1,5 с | Сервер + сеть, без времени SSO |
| p95 расчёта комплекта | ≤ 2,0 с | От принятого запроса до полного ответа |
| p95 импорта в корзину | ≤ 3,0 с | Включая вызов корзины ОМА |
| p95 создания брони мастера | ≤ 4,0 с | Включая расписание партнёра |
| p95 приёма Proof после загрузки | ≤ 5,0 с | Проверка, очистка и запись метаданных |
| p95 ответа AI | ≤ 10,0 с | После timeout — детерминированный fallback |
| Свежесть цены | По контракту ОМА; рекомендуемо ≤ 5 мин | Разница `observedAt` и текущего времени |
| Свежесть доступности | По контракту ОМА; рекомендуемо ≤ 60 с | Разница `observedAt` и текущего времени |
| Технические ошибки расчёта | < 0,5% | Ошибки / принятые расчёты |
| Дубли от повторного импорта | 0 | Аудит idempotency key |
| Критические утечки данных | 0 | Реестр инцидентов |
| Неодобренные версии правил в production | 0 | Журнал публикаций |

SLA для пользователя должен следовать из подтверждённых upstream-SLA. Если API ОМА не обеспечивает свежесть или доступность, соответствующий показатель нельзя обещать публично.

## Definition of Done сценария

- утверждены владелец и эксперт;
- определены входы, единицы измерения и допустимые диапазоны;
- каждое правило ссылается на проверяемый источник;
- есть positive, negative, boundary и abuse-case тесты;
- описаны отсутствие товара, изменение цены и деградация интеграции;
- пройдены accessibility, privacy и security review;
- настроены метрики, алерты и поддержка;
- подготовлен откат версии;
- продуктовый владелец подписал критерии приёмки.

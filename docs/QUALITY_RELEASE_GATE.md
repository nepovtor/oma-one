# OMA ONE — контроль качества перед защитой

Ветка разработки: `feature/oma-quality-service-flow`. Этот документ описывает проверяемые критерии качества, а не готовность к реальным продажам.

## Главный путь клиента — 10 шагов

1. Открыть HOME TWIN 3D и увидеть план квартиры.
2. В OMA ONE выбрать задачу «Установить полку».
3. Для гипсокартона и бетонного крепежа AntiFail должен заблокировать список покупок.
4. Исправить крепёж, проверить условия и получить только предварительно допустимый комплект (не сертификат безопасности).
5. Указать свои материалы: ZeroBuy меняет смету.
6. Сохранить проект; открыть «Помощь мастера», выбрать услугу, желаемый день и слот, увидеть условную цену.
7. Сохранить демо-заявку. Система должна явно сообщить, что **она не отправлена мастеру**. Перезапустить приложение — запись сохраняется. Отмена позволяет создать новую заявку для этого проекта.
8. Сформировать демо-корзину. Реальных заказов/платежей нет.
9. Завершить этапы Domino, записать личное выполнение в Proof. HOME TWIN показывает полку лишь после этого; фотография не равна заключению эксперта.
10. Переключить «готовый вид» / «к прогрессу»: визуальная цель не меняет сохранённые статусы и проценты.

## Автоматические проверки

```bash
npm ci
npm run typecheck
npm run check:ios-evidence
npm run test:proof
npm test
npm run test:e2e
xcodebuild -project ios/OMAOne.xcodeproj -scheme OMAOne \
  -configuration Debug -sdk iphonesimulator \
  -destination "generic/platform=iOS Simulator" CODE_SIGNING_ALLOWED=NO build
```

Файл `.github/workflows/quality.yml` запускает Linux проверки Node/PostgreSQL/Playwright и отдельную сборку iOS на GitHub macOS 26. Статус CI считается подтверждённым **только после реального успешного завершения на текущем SHA**.

## Принципиальные ограничения

- Демо-заявка сохраняется в UserDefaults и не уходит в ОМА, мастерам или платёжные системы. Цена — только сценарный ориентир, не публичный тариф и не оферта.
- Не собираем адрес или телефон для демо-заявки. Поле комментария предназначено только для краткого безопасного описания задачи.
- iOS использует локальные модели и демо-каталог. Реальные товары, остатки, бонусы, платежи, МТБанк и API ОМА **не подключены**.
- HOME TWIN — вручную смоделированная квартира 80 м². Она не отсканирована из фото пользователя и не предназначена для обмера.
- Восемь механизмов работают на тестовых данных. Расчёты бизнес-эффекта, процент возврата, стоимость привлечения и экономия пока **гипотезы**.
- Проверка крепежа не заменяет инженерную экспертизу; фото и личный отчёт не дают статуса `EXPERT_VERIFIED`.
- Производительность и стабильность 3D на физическом iPhone требуют отдельной проверки, даже при успешной сборке симулятора.

## GO / NO-GO

**GO:** оба CI-джоба успешны; Xcode билд собирается; весь путь 1–10 пройден на устройстве без падений; есть резервное видео; ведущий не делает не подтверждённых заявлений.

**NO-GO:** нарушение AntiFail, потеря Proof/заявки, ложное сообщение о принятии заявки, аварийное завершение приложения, несоответствие расчёта корзине.

Для пилота необходимы реальные разрешения, каталог/API, исполнитель и договорные условия, безопасность хранения персональных фото и результатов, исследование пользователей и подтверждённая экономика.

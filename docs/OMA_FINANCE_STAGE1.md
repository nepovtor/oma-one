# OMA Finance — Stage 1 и путь к банковскому партнёру

OMA Finance в этой ветке — неофициальный демонстрационный подбренд OMA ONE. Он объединяет синтетический банковский кабинет и управление бюджетом жилья, но не хранит и не переводит реальные деньги, не выпускает платёжные инструменты и не является банковским продуктом ОМА.

## Что работает в Stage 1

- iOS и PWA: счёт в BYN, замаскированная виртуальная демо-карта, управление её локальными настройками, фильтруемый журнал синтетических операций.
- Перевод и пополнение добавляют только синтетическую запись и меняют только демонстрационный остаток.
- Бюджеты нескольких проектов: материалы после ZeroBuy, ручная стоимость услуг, доставка, дополнительные расходы, резерв и превышение лимита.
- План расходов с зависимостями Domino; `MANUALLY_PAID` не создаёт банковскую операцию, а Proof не запускает перевод.
- Аннуитетный калькулятор и личные цели накопления без заявки, скоринга или банковского счёта.
- Локальное восстановление на iOS и PWA; PWA дополнительно сохраняет DEMO-состояние владельца в PostgreSQL с оптимистичной ревизией.

Данные аккаунта, карт, операций, цен и целей синтетические. `LIVE` заблокирован в UI, схемах API, PostgreSQL-ограничении и provider adapter.

## Запуск демонстрации

```bash
npm install
npm run db:up
export DATABASE_URL='postgresql://oma:oma@127.0.0.1:55432/oma_one'
export OMA_BANKING_MODE=DEMO
npm start
```

Откройте <http://localhost:8787/?view=finance>. Для iOS откройте `ios/OMAOne.xcodeproj`, соберите схему `OMAOne` и выберите вкладку «Финансы». Нативный Stage 1 работает без сервера и хранит только синтетическое состояние в `UserDefaults`; платёжные реквизиты там не сохраняются.

## Сценарий выступления (4–5 минут)

1. Открыть «Финансы», показать отметку DEMO, синтетический баланс и замаскированную карту.
2. Добавить перевод на 25,50 BYN: показать изменение демонстрационного остатка и новую запись, не утверждая, что деньги ушли.
3. Открыть историю, отфильтровать покупки и домашние проекты; пояснить разницу `AUTHORIZED` и `SETTLED`.
4. В бюджете изменить стоимость мастера и показать пересчёт остатка или превышения; материалы уже учитывают результат ZeroBuy один раз.
5. В плане платежей отметить этап вручную и подчеркнуть, что это не транзакция и Proof не переводит деньги автоматически.
6. Пересчитать финансирование и создать цель; перезапустить приложение и показать восстановление.
7. Завершить схемой Stage 2/3 и списком внешних блокеров ниже.

## Архитектура интеграции

`finance-domain.ts` содержит точные расчёты в минимальных денежных единицах. `banking-provider.ts` задаёт единый контракт для `DemoBankingProvider`, строго не настроенного `SandboxBankingProvider` и заблокированного `LiveBankingProvider`. PWA использует `GET/PUT /api/v1/finance`; запросы требуют текущую сессию, CSRF для записи, строгую Zod-валидацию и ревизию. Владельцем всегда является пользователь сессии, а не `userId` из тела.

Stage 2 начинается только после получения официальной Sandbox-документации и доступов. Stage 3 требует отдельного рассмотренного изменения: переменная окружения сама по себе не может включить LIVE.

## Что необходимо от партнёров

- Лицензированный банк-эмитент или регулируемая банковская платформа: счёт, KYC/AML, выпуск и обслуживание карт, лимиты, статусы операций и возвраты.
- Официальный Sandbox с OpenAPI/SDK, моделью OAuth/mTLS, тестовыми пользователями, idempotency contract, подписанными webhook и правилами сверки.
- Поддерживаемая партнёром платёжная сеть с подтверждённой географией, валютами, NFC и системными кошельками.
- Юристы и compliance партнёров: роли ОМА/OMA ONE, согласия, маркетинг по транзакциям, сроки хранения, удаление и трансграничная передача данных.
- Официальные API ОМА для каталога, цен, корзины, заказов, возвратов и услуг; текущие данные не являются такими API.

## Блокеры реального запуска

- **Юридические:** договоры, допустимая модель продукта в Беларуси, лицензированная сторона, KYC/AML, правила платёжной сети, пользовательские документы и согласия, PCI DSS scope, политика данных и инцидентов.
- **Технические:** токенизированные hosted-компоненты, MFA/SCA для критических действий, mTLS/TLS, secret manager/HSM по требованиям партнёра, подписи и replay-защита webhook, reconciliation, fraud/risk controls, мониторинг и disaster recovery.
- **Организационные:** независимый security review, threat model, penetration test, SLA и поддержка спорных операций, chargeback/возвраты, аудит релиза и управляемое включение функций.

До закрытия этих пунктов продукт остаётся Stage 1. Не вводите PAN, CVV/CVC, PIN, паспортные снимки или реальные банковские токены в этот контур.

## Проверки

```bash
npm run typecheck
npm run test:proof
npm test
npm run check:ios-evidence
npm run test:e2e
xcodebuild -project ios/OMAOne.xcodeproj -scheme OMAOne -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

E2E проверяет полный DEMO-путь PWA и отсутствие горизонтального переполнения на ширине 320, 375 и 390 px. Dynamic Type, VoiceOver и физический iPhone требуют отдельной ручной проверки перед публичной демонстрацией.
